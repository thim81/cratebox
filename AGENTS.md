# Repository instructions

- The user does not like Git worktrees. Work in the current checkout by default; create a worktree only when the user explicitly asks for one.
- For local UI work and interactive verification, use the Codex embedded browser; do not switch to an external browser or native Chrome. Verify behavior in the embedded browser when the app and required local services are available, rather than relying only on a build.
- Custom MCP source, tests, Python project configuration, lockfile, and setup documentation live in `cratebox/rekordbx-mcp/`. Run uv from that directory, or use `uv --directory cratebox/rekordbx-mcp ...` from the repository root.

## Application domains

- **CrateBox UI** presents playlists and collection results and handles user interaction. It talks to the CrateBox API, not directly to Rekordbox or the Rekordbox MCP.
- **CrateBox API** is the UI's application interface. It coordinates playlist operations and collection lookups, and serves audio to the UI. It owns app-specific behavior and keeps local file paths on the server; browser responses must not contain audio paths. CrateBox may update embedded cover artwork or the embedded star rating of an MP3/M4A selected from an app-owned crate or verified Rekordbox playlist membership. Rating edits must target the track loaded in the deck and update only the file's rating tag. Stage and verify the update before atomically replacing the selected audio file; preserve audio data and other metadata, and do not retain a backup. This does not authorize any other audio edits or changes to the Rekordbox database, playlists, XML exports, analysis files, or metadata.
- **Rekordbox MCP** is a consumer-neutral data provider for the local Rekordbox collection. It owns snapshot-backed collection access and exposes generic collection data and operations. Do not add CrateBox-specific tools, configuration, playback behavior, or assumptions to the MCP. Consumers such as the CrateBox API adapt the generic MCP contract to their own features.

- **Never change or alter the original Rekordbox database, playlists, XML exports, analysis files, or metadata.** Audio files remain read-only except for the explicit CrateBox embedded-cover and loaded-track rating operations described above. Use temporary byte-for-byte copies or exported snapshots for inspection and testing, and write generated artifacts only outside the original Rekordbox data locations.
- Use uv for Python environments, commands, and tests. Use the native macOS launcher; do not use Docker.
- CrateBox API source and tests live in `cratebox/`; MCP source and tests live in `cratebox/rekordbx-mcp/`.
- Configure MCP clients to launch `rekordbx-mcp start`: when Rekordbox and its agents are closed, create and verify a fresh read-only snapshot, then launch the MCP against that copy. When Rekordbox or its agents are running, reuse only the newest existing snapshot after verifying it, and report that an existing snapshot is being used; do not read or copy the live database. Startup must fail if process checks, required copying, or snapshot verification fail, or if no snapshot is available while Rekordbox is running. Do not fall back to an older snapshot when the newest is invalid. Keep the explicit snapshot path, read-only connection, SQL authorizer and tool allowlist. The worker uses normal user permissions; do not claim OS filesystem or network isolation.
- Keep upstream unmodified and pinned. Use `rekordbx-mcp update-upstream` for explicit upgrades with compatibility tests and rollback. Upgrading must not automatically expose new tools or weaken the snapshot or read-only database protections.
- Playlist export accepts either ordered track IDs or ordered absolute file locations, resolving both through the verified snapshot. File locations must match exactly one active snapshot track; never export unregistered files. The playlist exporter may insert only the fixed separator WAV references from the user's supplied separator folder, and each must resolve to exactly one active snapshot track. Write M3U8 files only in the repository's `playlists/` directory and CrateBox JSON metadata in `.cratebox/crates/`. Existing JSON files in `output/` stay untouched and are not read or migrated. Update existing files only after explicit user confirmation, follow no destination-directory symlink, and import nothing into Rekordbox. Keep audio paths out of browser API payloads and conversational MCP client allowlists. Any path access needed by a local application must use a generic MCP data contract; keep app-specific decisions and playback in that application's API. A separate playlist uses a different name. The exporter creates external files, so its MCP annotation must not claim it is read-only.
